# Как я выгружаю очередь

В очереди я выбираю ровно одну currency и нажимаю CSV. Сервер проверяет сессию,
merchant scope, текущий canonical run и читает все выбранные строки одним
REPEATABLE READ snapshot. CSV — новый срез в exported_at, а не склейка прежних
страниц. При смене canonical head возвращаю409 и перечитываю очередь.

Я сохраняю filters merchant/currency/rule/status/presence/age/assignee. Параметры
страницы after/limit запрещаю, лимит10000строк проверяю до выдачи файла. При
переполнении отказываю целиком, не обрезаю результат. Пустой срез содержит заголовок.
В каждой строке есть exported_at/run/as_of/knowledge_at, версии finding/workflow,
case/order/currency/rule, presence/status/assignee. Raw payload, комментариев,
паролей и cookie в выгрузке нет. Общий денежный итог не вычисляю.

UTF-8 BOM помогает открыть файл в табличном редакторе. csv.writer экранирует
разделители/переводы строк; потенциальные формулы я дополнительно превращаю в
текст префиксом apostrophe, включая формулу после пробела/BOM. Один CSV quoting
не защищал бы от выполнения формул. Ответ no-store/nosniff, имя файла фиксировано,
SHA256 в заголовке позволяет проверить точные байты. Скачанный файл уже находится
под ответственностью оператора: браузерный logout его не удаляет.

Я меняю состав выгрузки в queue_export.COLUMNS и SQL вместе. Упражнение: выбрать
RUB/status=all, сверить case_key и workflow_version с карточкой, затем изменить
комментарий и выгрузить снова. Ожидаю прежний финансовый run, новую человеческую
версию и новое exported_at; старый скачанный файл остаётся прежним.
