## Открытые решения без блокирования текущей работы

O01: отдельный deadline refund — требуется новый контракт; первый settle_after общий.
O02: источник correction/reversal — v1 требует неизменяемость, спорные факты в карантине.
O03: retention raw/истории — по умолчанию ничего не удаляем автоматически.
O04: SSO — не нужен для локального портфолио; real deployment потребует отдельного решения.
O05: комиссия PSP на уровне batch — не распределяем на заказы, пока нет правила провайдера.
O06: 24.10.2026 я решил вести ежедневные мини-проекты отдельно.
Существующую автоматизацию не переключать на CommerceGuard. Флагман продолжается
отдельными последовательными срезами; отдельного расписания для него пока нет.

Допущения фиксируются один раз для текущего среза; если появляется новый существенный
факт, он становится явным изменением контракта/ADR. Избегать рефакторинга ради вкуса,
но не выдавать известную ошибку за «решение, которое нельзя пересмотреть».

## Уточнения CG-103

- R02: полный EOF/COPY и publish одним COMMIT написаны, но не исполнялись.
- R07: orphan raw/manifest возможен; discovery и persistent failures — CG-104.
- Новый риск: hard links/fsync зависят от filesystem; Windows/Linux не проверены,
  сетевые/облачные папки не заявлены поддержанными. Нет WORM или backup.
- Earlier observed_at старого PSP сознательно отклоняется; correction contract
  нужен до обработки таких исправлений. Source time не заменяет knowledge cutoff.
- Legacy ingest_batch с данными блокирует 0002. Автоматической очистки/backfill нет.
