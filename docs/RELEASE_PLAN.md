# Как я довожу CommerceGuard до первой рабочей версии

Я фиксирую объём первой версии для одного экземпляра организации: OMS/PSP файлы,
сверка и settlement, воспроизводимые отчёты, рабочее место с ролями и аудитом,
экспорт, пересчёт периода, резервирование/восстановление, диагностика и управляемая
поставка. Свою учебную историю сохраняю честно; реальные компании и опыт не выдумываю.

| Шаг | Результат | Текущее состояние |
| --- | --- | --- |
| CG-405 | Согласованный ограниченный CSV выбранной очереди | Я реализую |
| CG-501 | План диапазона и возобновляемый backfill | Далее |
| CG-502 | Проверяемый комплект DB+raw и восстановление в пустую БД | Далее |
| CG-503 | Health/readiness, метрики и безопасные структурные события | Далее |
| CG-504 | WSGI server, изолированная поставка, секреты и старт/стоп | Далее |
| CG-505 | Фактический EXPLAIN и проверка ограничений нагрузки | Далее |
| CG-601 | Воспроизводимая сквозная демонстрация | Далее |
| CG-602 | Руководство изменения и сопровождения | Далее |
| CG-603 | Общая приёмочная матрица, CI, архив и версия | Далее |

Я не заменяю проверку стабильности сменой номера. Перед stable release проверяю
чистую установку и миграцию, нормальный путь, отказ/повтор, роли/CSRF, конкурентное
решение, реальное восстановление, запуск поставки и CI. Конкретные версии, среду,
время, ограничения и известные дефекты фиксирую в RELEASE_CHECKLIST и VALIDATION.
Внешний доступ включаю только с корректным origin/TLS; локальный запуск остаётся
безопасным значением по умолчанию. Постоянные службы самопроизвольно не устанавливаю.
