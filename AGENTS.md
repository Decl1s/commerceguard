# Продолжение CommerceGuard

Это отдельный флагманский проект, начат 24.10.2026; не ежедневный мини-проект.
Приоритет — мои актуальные решения о проекте.

- Пиши все объяснения и важные комментарии на русском.
- Я выбрал режим без исполнения: не запускать приложение, demo, импорт,
  py_compile/compileall, unit/smoke/integration, линтеры, type check, сборку,
  SQL/миграции, контейнеры или CI. Не создавать workflow со скрытым исполнением.
  Этот режим действует до моего отдельного явного решения о запуске.
- Статус исходников unverified. Не заявляй «работает», «проверено», «готовый бизнес-релиз».
- Один заход — один небольшой срез текущего спринта; весь backlog за раз не реализовывать.
- Я веду ежедневные мини-проекты отдельно от флагмана с 24.10.2026. Не менять
  существующую автоматизацию на флагман; отдельное расписание для него не создано.
- Сначала читай README, docs/KANBAN.md, docs/WORKLOG.md, текущий docs/sprints/*.md,
  docs/DATA_CONTRACTS.md и применимые ADR в DECISIONS.md.
- Текущий этап и сделанное я фиксирую в таблице:
  docs/PROGRESS.md — постоянная точка прогресса, обновлять каждый срез.
- Сейчас S1, CG-101/102 написаны без исполнения, в Review. Следующий pull — CG-103:
  постоянный raw, batch manifest в БД, staging/COPY и атомарная публикация.
- Текущая ветка codex/s1-cg102-file-contracts. Начало S1 — docs/sprints/S1.md,
  схема — docs/STORAGE.md, файловый контракт/API — docs/INPUTS.md, ADR-13…16.
- CG-102 строится поверх CG-101 (Draft PR #10), который строится поверх S0 #1;
  main остаётся навигацией. Читать текущую ветку и PROGRESS, а не устаревший S0.
- Текущий CG-102 опубликован в Draft PR #11; следующую ветку строить от его
  актуальной удалённой истории, без force push и без автоматического принятия PR.
- open_input() — один проход с обязательным EOF; summary недоступен до конца.
  До COPY определить temporal dedup относительно append-only core. Не считать
  внутрипакетную дедупликацию parser уже реализованным повтором публикации в БД.
- Публичная разработка: Decl1s/commerceguard, codex/sprint-0-foundation, Draft PR #1.
  Карточки и ссылки есть в docs/KANBAN.md. Main пока содержит стартовую страницу;
  не принимать PR и бизнес-истории автоматически без отдельного решения о приёмке.
- При изменении этапа обновляй доску, фактический журнал, технологии, ограничения
  и точку продолжения в этом файле. Состояния процесса определены docs/PROCESS.md.
- Код независимого предметного слоя не связывать с UI/оркестратором/драйвером БД.
- Все входы только синтетические. Контакты, секреты, документы, приватные пути,
  реальные выгрузки, .venv, workspace и данные не входят в исходники публикации.
- У проекта собственный Git. Перед git add сравни root с папкой commerceguard;
  индексируй только явный PUBLIC_FILES.txt. Никогда не используй родительский Git.
- Ветки codex/. Удалённая история через API может отличаться от локальной;
  сохраняй фактического удалённого родителя, не делай force push.
- Публикуй этапы как разработку и Draft PR; не создавай фиктивный стабильный релиз.
- Административные операции чтения, Git и просмотра публикации допустимы; они
  не заменяют и не подразумевают исполнение приложения.
- Не изменяй sources/ и пользовательские изменения других приложений.

## Авторский стиль

Комментарии, описания, документацию, PR и записи о решениях веду от первого лица
единственного числа: «я выбрал», «реализовал», «сохраняю», «пока не запускал».
Не использую пересказ поручений вроде «пользователь попросил» или «по запросу
пользователя». Технические определения, названия команд и роли пользователей
продукта сохраняю. Статус учебного проекта и фактические результаты проверок
описываю точно; планы не называю реализованными возможностями.
